### Rulings

Ruling: the concurrency test's `assert provenance._git(repo, "fsck", "--no-progress") == "" or True` is replaced by a bare `_git(repo, "fsck", "--no-progress")` call with a comment saying the call itself is the assertion — `fsck` exits non-zero on a corrupt object store and `_git` raises on that, so there is nothing to compare against and the `or True` made the whole line unfailable. This is the sixth vacuous assertion caught in this repo and the first one I wrote myself. Cost if wrong: none; the fix is strictly stronger than what it replaces.

Ruling: `_git` owns the git environment, not `_commit`. It is built once in the runner for every call — `PATH`/`LANG` inherited, `GIT_*_NAME` of "ScieFlow", both email variables set, dates left to git — and `os.environ` is never copied. Two reasons: a missing global `user.email` makes `commit-tree` fail on a fresh machine, and one construction point means no later call site can accidentally inherit the serve process's environment, which is the discipline `preview.compile_env` already applies for latexmk. Cost if wrong: commits carry a fixed identity rather than the user's, which is correct for a derived repo but would need revisiting if these commits ever became something a human authored.
